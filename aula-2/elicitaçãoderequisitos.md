ATIVIDADE  MAKING HISTORY

1. REFINAMENTO
2. Cliente  acompanhar pedido
Necessidade vaga:
“O usuário precisa acompanhar o pedido depois da compra.

Histórias refinadas:
Como cliente, quero ver o status atual do meu pedido, para saber em que etapa ele está.


Como cliente, quero receber uma atualização quando o status do pedido mudar, para saber quando o pedido avançar para a próxima etapa.
Como cliente, quero ver uma previsão de entrega, para saber aproximadamente quando meu pedido chegará.
2. Restaurante — item indisponível
O restaurante precisa avisar quando um item do cardápio fica indisponível.”
Histórias refinadas:

Como restaurante, quero marcar um item como indisponível, para evitar que clientes façam pedidos desse produto.
Como cliente, quero ver quando um item está indisponível, para não tentar comprar um produto que não está disponível.
Como restaurante, quero tornar um item disponível novamente, para voltar a aceitar pedidos desse produto quando houver estoque.
3.Entregador — reportar problema
Necessidade vaga:
“O entregador precisa reportar um problema durante a entrega.”
Histórias refinadas:
Como entregador, quero selecionar o tipo de problema ocorrido durante a entrega, para informar rapidamente o que aconteceu.
Como entregador, quero adicionar uma observação ao problema, para fornecer mais detalhes sobre a ocorrência.
Como entregador, quero enviar o problema para o suporte, para receber ajuda e conseguir concluir a entrega.
2.PRIORIZAÇÃO MOSCOWMULE
- MUST Sem isso, o produto não serve:
Como cliente, quero ver o status atual do meu pedido, para saber em que etapa ele está.
Como restaurante, quero marcar um item como indisponível, para evitar que clientes façam pedidos desse produto.
Como cliente, quero ver quando um item está indisponível, para não tentar comprar um produto que não está disponível.
 Como entregador, quero selecionar o tipo de problema ocorrido durante a entrega, para informar rapidamente o que aconteceu.
- SHOULD — Importante, mas não obrigatório:
Como cliente, quero receber uma atualização quando o status do pedido mudar, para saber quando o pedido avançar.
Como entregador, quero enviar o problema para o suporte, para receber ajuda e conseguir concluir a entrega.
- COULD — Entra se sobrar tempo:
Como cliente, quero ver uma previsão de entrega, para saber aproximadamente quando meu pedido chegará.
Como entregador, quero adicionar uma observação ao problema, para fornecer mais detalhes sobre a ocorrência.
Como restaurante, quero tornar um item disponível novamente, para voltar a aceitar pedidos desse produto.
- WON'T Fica para depois:
Rastreamento do entregador em mapa em tempo real, para uma primeira versão do produto.
